# aria.iiitr.ac.in

ARIA — AI Research & Innovation Arena. Standalone static site, migrated from the
`/aria` section of the main [iiitr.ac.in](https://iiitr.ac.in) repo so it can be
deployed independently on its own subdomain.

## Structure

- `index.html` — ARIA home page
- `coe-ai.html` — Centre of Excellence in AI
- `partners.html` — Partners & MoUs
- `404.html` — not-found page (served automatically by Vercel for unmatched paths)
- `assets/` — logo, stylesheet, script, and images (leadership photos and hero
  background copied over from the main site so this site has no cross-origin
  asset dependency)

No build step — plain static HTML/CSS/JS. Links to pages that still live on the
main site (`/reach_us.html`, `/faculty/...`) point to the absolute
`https://iiitr.ac.in/...` URL.

## Deploy

Deploys are driven by GitHub Actions (`.github/workflows/dev.yml` and
`prod.yml`), mirroring the pattern used by the main
[iiitr.ac.in](https://iiitr.ac.in) repo — minus the Ruby/Jekyll build steps,
since this repo has no build step at all:

- **`dev.yml`** — on every PR into `master`, builds and deploys a Vercel
  preview, then comments the preview URL on the PR.
- **`prod.yml`** — on every push to `master`, deploys straight to production.

### One-time setup

1. Create the Vercel project first (`vercel link` from your machine, or
   import it in the dashboard once) so it exists for the CLI to target. In
   **Project Settings → Git**, disconnect/disable the GitHub integration's
   auto-deploy — the Actions workflows call the Vercel CLI directly, so
   leaving Vercel's own Git integration connected will double-deploy every
   push and PR.
2. Add these repo secrets (**Settings → Secrets and variables → Actions**):
   - `VERCEL_TOKEN` — a Vercel personal access token.
   - `VERCEL_EMAIL` — the email used for the git-identity-amend step (the
     project's author attribution in Vercel's dashboard; purely cosmetic).
   - `VERCEL_PROJECT_NAME` — the Vercel project's name (from
     `vercel.json`/the dashboard).

No build command or output directory settings are needed beyond that —
`vercel build` passes this static site through unchanged.

### Caching (`vercel.json`)

Image assets (`/assets/images/*`, `/assets/logo.jpg`) are cached for a year
with `immutable`, since they're referenced by a fixed filename with no content
hash. **If you ever replace one of these files in place (same filename, new
content), browsers that already cached it won't see the change for up to a
year.** Rename the file (and update the references to it) instead of
overwriting it, or bump the cache duration down temporarily if you need an
in-place swap to show up quickly.

`aria.css` and `aria.js` are cached for only 10 minutes (`must-revalidate`)
since they're still actively edited — safe to overwrite in place.

## SEO

The main [iiitr.ac.in](https://iiitr.ac.in) site is Jekyll and gets its
canonical/Open Graph/Twitter-card/JSON-LD tags auto-generated per page by the
`jekyll-seo-tag` plugin (from `_config.yml` + each page's front matter), and
its `sitemap.xml` auto-generated by `jekyll-sitemap`. This repo has **no
build step**, so there's no plugin to do that — the equivalent tags are
hand-written into each page's `<head>` instead:

- `<link rel="canonical">`, `og:*`, `twitter:*` meta tags, and a JSON-LD
  `Organization` block, all hardcoded per page in `index.html`, `coe-ai.html`
  and `partners.html`.
- `robots.txt` and `sitemap.xml` at the repo root, hand-maintained.

**If you add a new page or change a page's title/description, update all
three in that page's `<head>` together** (the plain `<title>`/`<meta
name="description">`, the matching `og:title`/`og:description`/
`twitter:title`/`twitter:description`, and the JSON-LD block if present) —
nothing keeps them in sync automatically the way Jekyll does on the main
site. Add new pages to `sitemap.xml` too.

All canonical/OG/sitemap URLs assume the production domain
`https://aria.iiitr.ac.in` — update them if the domain changes.
